# Seedream Flash / Lite / Pro 路由调研

日期：2026-10-22（北京时间）。代码与 dev 版本：`4954a5e`。

## 建议

可以做按任务选模型的路由。建议当前生产策略为：**Flash 处理普通任务，Pro 接受明确的高画质请求；Lite 保留为特定能力的临时选项，不加入长期默认自动路由。**

三款模型并非简单的低、中、高档关系。先检查功能是否支持，再考虑画质偏好、费用、剩余时间和模型生命周期。不能把模型名字、提示词长度或是否出现“海报”当作主要判断条件。

本次完成官方资料核对、当前接口能力检查，以及三类任务、每类三模型共九张实际生图和逐图目视检查。

后续实施：已按调用方传入画质偏好的方案增加 `quality`，`standard` 选择 Flash、`high` 选择 Pro；显式 `model` 优先，两者均省略时保留服务默认值。下文的调研和接口差距以调研时的 `4954a5e` 为基线。预算与取消仍由 #28 单独处理。

## 能力与价格边界

| 需求 | Flash | Lite | Pro | 路由影响 |
|---|---|---|---|---|
| 普通单图、插画、商品图 | 支持 | 支持 | 支持 | 默认 Flash |
| 单 / 多参考图编辑 | 支持 | 支持 | 支持 | 有参考图本身不足以选择 Pro |
| 更高画质的成稿 | 可作为基线 | 需按任务评测 | 官方定位画质优先 | 明确高画质时优先评测 Pro |
| 3K / 4K 输出 | 不支持该档位 | 支持 | 不支持该档位 | 高分辨率需求不能直接等同于 Pro |
| 原生联网、组图、流式返回 | 不支持 | 支持 | 不支持 | Lite 的差异主要在这些能力 |
| 图层拆分 / 透明图编辑 | 支持，存在输入限制 | 不支持这些专属能力 | 支持，存在输入限制 | 这些功能也不要求一律选 Pro |

尺寸和参考图限制见[官方图片生成 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)。Lite 的搜索、组图与流式能力见[官方系列教程](https://docs.volcengine.com/docs/ark/seedream-4-0-5-0?lang=en)。Pro / Flash 的定位及专属编辑能力见[官方教程](https://docs.volcengine.com/docs/ark/seedream-5-0-pro?lang=en)。

| 模型 | 单图生成的输出刊例价 | 输入参考图费用 |
|---|---|---|
| Flash | ¥0.12 / 张 | 免费 |

**生命周期限制：**当前 Lite 的 `doubao-seedream-5-0-260128` / `doubao-seedream-5-0-lite-260128` 已停止新购，计划于 **2026-11-24 14:00（UTC+8）** 下线。本次账号仍可调用，不代表新账号能开通，也不代表适合建立长期依赖。来源：[官方下线公告](https://docs.volcengine.com/docs/ark/model-deprecation-notice?lang=en)。

## 九张实际对比

通过 dev 的 `POST /v1/generate` 调用三款模型：显式传 `model`、`fallback_model=none`、`no_cache=true`，避免缓存或备用模型混入。九张均为 HTTP 200、请求模型与实际模型一致、上游尝试一次。

统一请求 `size=1536x1536`、比例 1:1。Flash / Pro 实际为 1536×1536；Lite 因原生最低像素要求实际为 1920×1920。这比较的是当前服务可提供的规格，不是严格同像素的模型基准。Pro 使用默认标准模式，没有开启 fast。

| 场景 | Flash | Lite | Pro |
|---|---:|---:|---:|
| 四行中文活动海报 | 10.12 秒 | 23.12 秒 | 44.04 秒 |
| 五物体、数量和位置约束 | 7.66 秒 | 29.55 秒 | 29.29 秒 |
| 根据参考图只修改杯子颜色 | 9.42 秒 | 19.19 秒 | 40.95 秒 |

耗时取服务器 `generation_finished.duration_ms`。Pro 编辑请求曾在客户端遇到一次 429，等待约 29 秒后才被接受，用户端总等待约 70 秒；表中排除了这段限流等待，保留服务实际处理时间。生产容量评估仍需另外统计用户端总等待。

按刊例估算九张输出费合计 **¥1.92**，编辑任务每次仅一张参考图，无额外 Pro 输入图费用。没有把被限流拒绝的请求记作一次生成。

### 目视检查结果

- **中文海报：**三个样本的四行文字均无明显错字、漏字或被主体遮挡。Flash 已能交付这个简单排版任务；Pro 样本的光影、道具与场景装饰更丰富，但这是单样本的审美观察，不能据此认定文字准确率更高。
- **物体布局：**三者均画出两个球、两个黄色方块和一只白杯，左右颜色、前后关系及把手方向基本符合要求。但三个样本均存在方块遮挡杯体的情况，未完整满足“全部可见且互不遮挡”；Lite 样本遮挡更明显。更高价模型也不能保证严格空间约束通过。
- **参考图编辑：**三者都将蓝杯改成橙红色，基本保留右侧把手、轮廓、视角、白底和主要高光。这个简单换色任务没有显示出必须升级 Pro 的证据；复杂局部编辑、多个产品一致性和人像身份保持还没有测试。

每个任务 / 模型只有一个随机样本，没有固定随机种子、盲评或独立 OCR。因此这些结果只能用于选型初筛，不能推导稳定成功率、p95、人物表现或所有中文海报的优劣。Lite 的 4K、原生搜索和组图能力本次仅核对文档，未做真实接口验收。

## 具体路由规则

| 请求情形 | 建议模型 / 行为 | 判断依据 |
|---|---|---|
| 草稿、日常配图、普通商品图、简单海报 | Flash | 单图能力够用，成本和实测等待更低 |
| 常规参考图换色、普通风格修改 | 先 Flash | 本次样本已完成；参考图不是升级信号 |
| 用户明确要求精修成稿、优先质感、愿意等待 | Pro | 使用明确画质偏好，先按约 1.5K 评测 |
| 严格中文排版或复杂构图 | 默认仍可 Flash；按验收结果升级 Pro | 不能只靠任务名字推断；字体、数量、位置要有检查标准 |
| 已收到 Flash 结果，用户明确要求更精细 | Pro | 属于用户要求的画质升级，应沿用已有参考图和约束 |
| 明确需要原生搜索、组图或 3K / 4K | 当前 Lite 可作为临时候选 | 先确认适配已支持该功能、账号可用、未到 EOS；生产默认禁用此自动分支 |
| 图层拆分、透明图编辑 | Flash 或 Pro，按画质偏好选择 | 两者都具备；先增加相应 API 契约 |
| 要求十分严格且任何几何改动都不接受的商品编辑 | 不能仅靠模型升级保证 | 可能需要遮罩、确定性图像处理和结果审核 |
| 模型不具备硬性要求或剩余时间不足 | 明确报不支持 / 预算不足，或使用经过验证的兼容方案 | 不静默降分辨率、丢图、移除搜索或违背明确画质要求 |

第一版建议只有两个常规入口：`quality=standard` 选 Flash，`quality=high` 选 Pro；未指定沿用 Flash。保留现有显式 `model` 的优先级。以后再加入经过验证的任务分类和能力要求，避免一开始引入不透明的自动猜测。

对于海报、复杂场景等软需求，调用方 Fusion 更了解用户目标，可将明确的画质偏好传给 image-service；服务负责能力校验、版本状态、预算和最终模型选择。第一版不需要额外调用一次 LLM 来判断每条 prompt。

不要默认“Flash 先画一张 → 视觉模型判断 → Pro 再画”：这会增加一次生图和判断成本。只有明确需要质量检查的工作流才开启，并设升级次数上限和整体等待预算。

## 与调研基线适配的差距

调研基线 `4954a5e` 中，`model` 省略时仅使用 `Settings.default_model`，没有按任务路由。扩展复杂路由时，需要考虑以下信息：

1. 模型能力声明：输出像素范围、参考图上限、原生搜索、组图、图层输出、透明通道及生命周期。
2. 请求意图：画质偏好与明确的功能需求；不能将 `grounding=true` 的旧兼容行为直接解释为必须使用 Lite。
3. 路由结果：记录请求偏好、选中模型、路由原因、策略版本及耗时；备用切换另记原因。
4. 缓存：在路由后按实际选定模型和有效参数计算，策略或输出语义变化时更新版本。

Lite 的独有能力目前多数没有对外适配：

- `grounding` 在 Seedream 路径不传搜索工具，Lite 当前也没有真正启用原生搜索。
- 请求 `size` 单边最多 2048，现有调用也没有表达 4K 档位。
- 公共参考图最多三张，未开放各模型的完整张数能力。
- 返回模型只有一个 `image_url`，尚不支持组图或图层数组，REST / MCP 也没有流式图片输出契约。

因此只增加一条“需要搜索 / 多图 / 4K 就选 Lite”的模型判断，并不能实现这些功能。若确定长期需要，应先设计接口和版本替代方案；当前 Lite 即将下线，不建议为它大规模新增长期专用功能。

对于真实产品外观，现有 `reference_subject` 可在外部找到参考照片，再交给 Flash / Pro。它不等同于模型原生联网：一般事实核对仍需由调用方先检索，并明确传入事实和图片依据。

## 与 Issue #28 的关系

按需求选择首个模型和遇到故障后换备用，是两个独立决策：

- 初始路由决定这次任务的功能与画质目标。
- 故障备用必须同时满足原目标、供应商可用性和剩余总预算。
- Flash / Lite / Pro 共享方舟账号与接口基础设施，账号欠费或方舟故障时，在三者间轮换通常没有意义；此时保留兼容的跨供应商备用。
- Pro 的较长处理时间不能突破 Fusion 的 150 秒上限。总等待预算必须包含参考图搜索、限流等待、上游调用和后处理；不能为了 `quality=high` 静默延长调用。
- 预算不足时，应说明不能满足所选模式；允许降低画质的请求才可以转 Flash。
- 自动选择 Lite 的任何临时分支都必须有下线日期约束，不能在 EOS 后静默改成不具备相同能力的 Pro。

本次采纳调用方显式传入 `quality` 的最小方案，预算与取消机制保留在 #28 独立处理。更复杂的自动分类或质量检查后升级，应在预算机制完成并收集真实业务样本后再决定。Lite 保持显式调用和能力验证的临时用途。
